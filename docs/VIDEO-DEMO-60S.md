# DataKeeper 60초 데모 촬영 시나리오

한 문서에서 `검수 대기 → 사람의 C 확정 → Skill 생성 → S/C 접근 차이 → 내용 없는 로그`를 보여 주는 60초 본편이다. 라이브 업로드와 긴 답변 설명은 본편에서 제외한다.

## 촬영 결론

- 본편은 `00_orion_60s_demo.md`를 미리 업로드한 상태에서 시작한다.
- 수정 대상인 `해지 조건 검토 메모`를 첫 카드에 배치해 스크롤을 없앤다.
- 영업팀원 S와 CEO C에게 **같은 질문**을 사용한다.
- 생성 답변의 문장보다 `C · 해지 조건 검토 메모 · 사용 근거 1`을 크게 보여 준다.
- 업로드 장면이 필요하면 별도 B-roll로 촬영하고 로딩 시작과 완료 사이를 점프 컷한다.

라이브 업로드는 분류 요청이 길어질 수 있고 모델 결과도 변할 수 있어 60초 본편에 넣지 않는다. 실제 Gemini로 분류한 결과를 사용하되, 촬영 직전 상태를 백업해 모든 테이크의 시작점을 같게 만든다.

## 사용할 문서와 검증 결과

촬영 파일: [`data/uploads/00_orion_60s_demo.md`](../data/uploads/00_orion_60s_demo.md)

임시 DB에서 현재 촬영 환경의 `gemini-3.5-flash` 모델로 두 번 분류했을 때 다음 결과가 반복됐다.
재현성이 중요하면 촬영 중 `GEMINI_CLASSIFICATION_MODEL`을 이 값으로 고정한다.

| 순서 | 섹션 | 1차 | 2차 | 화면에서 할 일 |
| ---: | --- | --- | --- | --- |
| 1 | 해지 조건 검토 메모 | S · 75% · 확인 필요 | S · 75% · 확인 필요 | C로 수정 |
| 2 | 외부 공개용 협력 안내 | O · 95% · 자동 확정 | O · 95% · 자동 확정 | 배지만 확인 |
| 3 | 내부 출시 운영안 | S · 90% · 자동 확정 | S · 90% · 자동 확정 | 배지만 확인 |
| 4 | 내부 협상 하한선 | C · 98% · 자동 확정 | C · 98% · 자동 확정 | 배지만 확인 |

두 번 모두 문서 최고 등급은 C, 확인 필요는 1개였다. 이는 리허설 결과이며 모델 출력에 대한 보장은 아니다. 본 촬영 전 실제 화면이 위 상태인지 확인한다.

## 촬영 전에 준비할 상태

다음 준비 과정은 영상에 넣지 않는다.

촬영은 대화 이력이 없는 새 브라우저 탭에서 시작하거나, 기존 탭이라면 영업팀원과 CEO의
`현재 대화 지우기`를 각각 눌러 프로필별 transcript를 비운다.

1. 촬영 전에 현재 DB를 반드시 백업한다. `app.init_samples --reset`은 실행하지 않는다.

   ```bash
   .venv/bin/python -c 'from app.db import backup_database; print(backup_database())'
   ```

2. 앱의 **분류·학습**에서 `00_orion_60s_demo.md`를 업로드한다.
3. 첫 카드가 `S · 신뢰도 75% · 확인 필요`이고 나머지 세 카드가 O/S/C 자동 확정인지 확인한다.
4. 업로드 직후, 아직 등급 수정과 질문을 하지 않은 상태를 다시 백업한다. 재촬영할 때 이 백업으로 돌아가면 Skill과 로그의 시작점을 같게 맞출 수 있다.
5. **권한 기반 질문**에서 `영업팀원 S`를 선택하고 아래 질문을 입력만 해 둔다.
6. **분류·학습**으로 돌아와 첫 카드의 `검토하기`를 열고 아래 수정 근거를 입력해 둔다. 등급은 아직 S로 둔다.
7. 학습된 Skill의 시작 개수를 기억한 뒤 녹화를 시작한다.

DB 복구 절차와 안전 수칙은 [5분 데모 운영 가이드](VIDEO-DEMO-SCENARIO.md)의 `촬영 후 원상복구`를 따른다.

## 복사할 문구

수정 근거:

```text
해지권은 향후 협상 전략과 결렬 기준을 노출하므로 C
```

본편 필수 질문 — 같은 문장을 두 번 사용:

```text
서비스 공급 중단 시 어떤 대응을 검토하고 있나요?
```

| 순서 | 사용자 | 질문 | 예상 결과 |
| ---: | --- | --- | --- |
| 1 | 영업팀원 S | 위 문장 그대로 | 관련 자료 없음 · 출처 0건 |
| 2 | CEO C | 위 문장 그대로 | C `해지 조건 검토 메모` · 사용 근거 1건 |

권한 비교 내레이션:

> 질문은 같지만, 확정된 C 섹션은 S 사용자의 검색에서 제외되고 C 권한 CEO에게만 근거로 제공됩니다.

## 권한별 추가 질문 세트

다음 질문은 선택 B-roll이나 75~90초 확장판에서 사용한다. **60초 본편에는 Q4만 사용**해 흐름을 유지한다.

```text
Q1. 소개 페이지는 누구나 볼 수 있나요?
Q2. 사내 출시 준비에 필요한 예산과 인력 계획은 무엇인가요?
Q3. 최소 보장액과 매출 배분율 수치를 알려주세요.
Q4. 서비스 공급 중단 시 어떤 대응을 검토하고 있나요?
```

| 검증 장면 | 시점 | 사용자 | 질문 | 예상 답변과 출처 |
| --- | --- | --- | --- | --- |
| 공개 정보 허용 | 자동 분류 후 | 외부 고객 O | Q1 | O `외부 공개용 협력 안내` 1건 · 2026년 11월부터 공동 프로모션 검토, 소개 페이지 공개 |
| 내부 정보 차단 | 자동 분류 후 | 외부 고객 O | Q2 | 관련 자료 없음 · 출처 0건 |
| 내부 정보 허용 | 자동 분류 후 | 영업팀원 S | Q2 | S `내부 출시 운영안` 1건 · 예산 4,800만 원, QA 4명, 9월 28일까지 점검 보고 |
| 기밀 정보 차단 | 자동 분류 후 | 영업팀원 S | Q3 | 관련 자료 없음 · 출처 0건 |
| 기밀 정보 허용 | 자동 분류 후 | CEO C | Q3 | C `내부 협상 하한선` 1건 · 최소 보장액 16억 5천만 원, 매출 배분율 14% |
| 검수 대기 차단 | C 확정 전 | CEO C | Q4 | 관련 자료 없음 · 출처 0건 |
| 확정 기밀 차단 | C 확정 후 | 영업팀원 S | Q4 | 관련 자료 없음 · 출처 0건 |
| 확정 기밀 허용 | C 확정 후 | CEO C | Q4 | C `해지 조건 검토 메모` 1건 · 30일 초과 중단 시 즉시 해지하는 방안을 검토 중이며 미확정 조건 |

실제 분류 결과의 요약·키워드까지 포함해 검색을 검증했으며, 모든 허용 사례는 대상 섹션만
정확히 1건, 모든 차단 사례는 0건이었다. 차단 장면에서는 권한 밖 정보의 존재를 추측하지 않고
화면의 중립적인 `관련 자료 없음` 안내만 설명한다.

위 회사명, 일정, 금액과 계약 조건은 모두 영상 촬영을 위한 가상 정보다.

## 촬영·편집 규칙

- 본편 조작은 C 선택, 확정, 질문 탭, S 전송, CEO 선택, 재전송, 로그 탭, 접근 로그의 8회로 제한한다.
- S 결과는 CEO로 바꾸기 전에 1초 이상 온전히 촬영한다. 사용자 변경 후 S 대화는 해당 프로필에 보존되고 CEO 대화와 섞이지 않아야 하며, CEO 생성 답변의 로딩은 0.5~1초만 남기고 점프 컷한다.
- 점프 컷은 대기 시간만 제거하며 S와 C의 실제 결과 화면은 이어 붙이거나 바꾸지 않는다.
- 답변 문구가 리허설과 달라도 다시 읽지 않는다. `사용 근거 1`, C 배지, 섹션 제목을 확대한다.
- `.env`, API 키, 터미널, 실제 알림과 고객 정보는 녹화 프레임에서 제외한다.
- 업로드 장면은 필요할 때만 1초 B-roll로 넣고 본편 타임라인에는 포함하지 않는다.

## 결과가 다를 때

| 상황 | 대응 |
| --- | --- |
| 첫 카드가 확인 필요가 아님 | 촬영을 시작하지 않는다. 모델 결과를 숨기거나 DB를 직접 고치지 말고, 촬영 전 백업으로 복구한 뒤 다시 업로드한다. 계속 달라지면 내레이션을 “사람이 자동 판정을 확정한다”로 바꾸고 pending 차단 주장은 뺀다. |
| 협상 하한선이 C가 아님 | 실제 결과를 기준으로 C로 사용자 확정한다. O/S/C 세 등급을 모두 한 화면에 보여 주는 장면은 생략해도 핵심 접근 비교에는 영향이 없다. |
| CEO 답변이 늦거나 실패함 | C 사용자 확정 상태와 API 설정을 확인한 뒤 해당 컷만 다시 촬영한다. 홍보 영상에서는 검색 폴백 오류 문구보다 실제 C 출처 카드가 보이는 성공 테이크를 사용한다. |
| 로그가 바로 갱신되지 않음 | `새로고침`을 누른 뒤 최신 항목을 다시 촬영한다. 질문·답변 본문이 없고 S/CEO 사용 섹션 수가 다른지 확인한다. |

## 최종 확인표

- [ ] 영상 길이가 55~60초다.
- [ ] `확인 필요 → C 사용자 확정 → Skill 생성`이 보인다.
- [ ] 같은 질문에서 영업팀원 S는 0건, CEO C는 C 출처 1건이다.
- [ ] 로그에 질문, 답변과 원문이 표시되지 않는다.
- [ ] 라이브 업로드와 긴 로딩을 본편에서 제외했다.
- [ ] 실제 정보나 API 키가 화면에 없다.
