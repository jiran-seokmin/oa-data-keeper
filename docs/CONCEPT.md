# DataKeeper — 접근 제어 엔진 (Access Control Engine) 컨셉 설계

> **DataKeeper** — All Data, Safe for Everyone (모든 데이터를, 모두가 안전하게) · 지란지교소프트 (이석민, 박종천)
>
> 한 줄 정의: **데이터 보안 등급(D) × 사용자 접근 등급(C) × 상황(Context)을 조합해, 섹션 단위로 5단계 접근 모드(A)를 실시간 판정하는 AI-네이티브 접근 제어 엔진.**
> 차단/허용의 이분법이 아니라 마스킹·추상화·노출 제한이라는 중간 단계를 제공해, 보안을 지키면서 데이터 활용을 최대화한다.

## 해커톤 MVP의 초점 (범위 확정)

**MVP는 "입력 데이터를 정해진 보안 등급으로 분류하고, 페르소나에 따라 접근이 제어되는 것을 시각적으로 보여주는 것"이다.**

- MVP = **① 분류** (문서 → 섹션 → D등급·엔티티·요약) + **② 판정** (D × C × Context → A모드) + **③ 시각화** (페르소나 전환 시 같은 문서가 다르게 보이는 뷰어)
- 실시간 질문에 LLM이 답변하는 질의응답 파이프라인은 **추후 구현(Phase 2)** — 본 문서 4.2절과 10장 로드맵으로 위치를 옮긴다.
- 데모의 증명 대상은 "AI가 답을 잘하는가"가 아니라 **"같은 데이터가 보는 사람에 따라 정확히 다르게 제어되는가"**다.

## 1. 해결하려는 문제

팀 노트·문서함·챗을 기반으로 팀 지식봇을 만들면 즉시 부딪히는 질문:

- **"팀 내부용 지식봇과 외부용 지식봇을 하나로 만들 수 있는가?"**
- "현재 논의 중인 고객사는 어디인가요?" — 영업팀에게는 답해야 하고, 외부 고객에게는 답하면 안 된다.
- "계약 고객사들의 예상 매출은 얼마인가요?" — 경영진에게는 숫자를, 팀장에게는 범위를, 그 외에는 차단해야 한다.

기존 접근법의 한계:

| 접근법 | 문제 |
|---|---|
| 봇을 내부용/외부용으로 분리 | 데이터 파이프라인 이중화, 지식 파편화, 유지비 2배 |
| 문서 단위 권한 (RBAC/ACL) | 문서 하나에 D1~D4 정보가 섞여 있음 → 문서 전체를 막으면 활용도 급감, 열면 유출 |
| 차단/허용 이분법 | "N개사와 논의 중" 같은 안전한 추상 답변조차 불가능 |
| 기존 DLP | 전송 시점 차단만 가능, AI가 컨텍스트로 소비하는 경로는 통제 불가 |

**핵심 통찰: 접근 제어를 "문서 단위 + 이분법"에서 "섹션 단위 + 5단계 그라데이션"으로 바꾸면, 하나의 지식봇이 모든 사용자를 서비스할 수 있다.**

## 2. 핵심 모델

### 판정 함수

```
A (접근 모드) = Engine( D (데이터 보안 등급), C (사용자 접근 등급), Context (부서·역할·목적·채널) )
```

### D — 데이터 보안 등급 (섹션 단위 부여)

| 등급 | 이름 | 예시 |
|---|---|---|
| D0 | 외부 정보 | 공개 제품 소개, 보도자료 |
| D1 | 일반 정보 | 사내 공지, 일반 회의록 |
| D2 | 제한 접근 정보 | 영업 파이프라인, 논의 중 고객사 목록 |
| D3 | 기밀 접근 정보 | 계약 조건, 고객사별 예상 매출 |
| D4 | 최고 접근 정보 | M&A, 인사 평가, 미공개 재무 |

### C — 사용자 접근 등급 (조직도 기반 부여)

C0(외부) ~ C4(최고). 조직도와 직급/직무를 기반으로 관리자가 부여. 외부 사용자·미인증 채널은 항상 C0.

### A — 접근 모드 (판정 결과, 섹션 단위 적용)

| 모드 | 이름 | 동작 |
|---|---|---|
| A0 | 전체 접근 | 원문 그대로 제공 |
| A1 | 노출 제한 | AI가 추론(개수 집계, 가능 여부 판단)에는 사용하되 내용을 직접 언급하지 않음 |
| A2 | 의미 제한 | 원문 대신 일반화된 요약만 제공: "제조 분야 3개사와 논의 중" |
| A3 | 정보 마스킹 | 엔티티를 타입 플레이스홀더로 치환: `[고객사A]`, `[금액]`, `[담당자]` |
| A4 | 접근 차단 | 섹션이 검색·컨텍스트에서 완전 제외. 존재 자체를 노출하지 않음 |

## 3. 판정 매트릭스 (기본값 — 관리자 튜닝 가능)

기본 규칙은 `gap = C − D`로 결정하고, 상황(Context)이 보정한다.

| gap | 기본 모드 |
|---|---|
| gap ≥ 0 | A0 전체 접근 |
| gap = −1 | A2 의미 제한 |
| gap = −2 | A3 정보 마스킹 |
| gap ≤ −3 | A4 접근 차단 |

**상황(Context) 보정 규칙 (ABAC 스타일, YAML 정책으로 관리):**

- **부서/직무 관련성**: 담당 부서의 데이터면 1단계 완화 (예: 영업팀원 C2가 영업 D3 문서 → A2가 아니라 A1)
- **목적(purpose)**: 질의 목적 선언이 데이터 용도와 불일치하면 −1단계
- **채널**: 외부 채널(외부용 봇 엔드포인트, 미인증 세션)은 D0만 A0, 나머지 전부 A4로 하드 캡
- **불변 규칙**: D4는 어떤 보정으로도 상승 불가. 보정 결과가 충돌하면 항상 낮은(안전한) 쪽 적용 (default-deny)

**D4 특칙 (최신 발표 슬라이드의 접근 권한 분석 표 기준):** D4 최고 접근 정보는 일반 gap 규칙이 아니라 별도 행을 따른다 — `C0/C1 → A4`, `C2 → A3`, `C3 → A1`, `C4 → A0`. 특히 D4 × C3은 A2(의미 제한)가 아니라 **A1(노출 제한)**으로 처리한다. 최고 기밀은 일반화 요약조차 내용(예: M&A 진행 사실)을 유출할 수 있으므로, AI가 **추론 근거로만 사용하고 존재만 고지**한다. 슬라이드 C3 샘플이 정확히 이 동작이다 — 인수 건의 이름·금액·일정을 일절 언급하지 않으면서 *"비공개 최고 전략 정보를 포함하여 분석하면 … 현금흐름 관리가 중요"*라는 결론만 제시한다.

## 4. 시스템 아키텍처 — 3개 파이프라인

> 단계 구분: **[MVP]** 수집 파이프라인 + 판정 엔진 + 시각화 · **[Phase 2]** 질의 파이프라인(실시간 AI 답변) · **[Phase 2~3]** 거버넌스 루프

```
[수집 파이프라인 · MVP]          [질의 파이프라인 · Phase 2]        [거버넌스 루프]
팀노트/문서함/챗/이메일          사용자 질의                        감사 로그
      │                              │                                │
  커넥터                         인증 → C·Context 결정              오분류 리포트
      │                              │                                │
  섹션 분리                      메타데이터 사전 필터                관리자 재라벨링
      │                          (A4 섹션은 검색에서 제외)              │
  LLM 분류기                         │                            키워드 규칙 개선
  (요약·키워드 추출·               섹션별 A모드 변환                    │
   D등급 제안+신뢰도)             (마스킹/추상화 적용 후                분류기 프롬프트/
      │                           프롬프트 조립)                     퓨샷 업데이트
  관리자 검수 큐                      │
  (저신뢰도만)                    LLM 답변 생성
      │                              │
  라벨링된 섹션 저장소            출력 가드 (유출 스캔)
  (벡터DB + D등급 메타)               │
                                  답변 + 감사 로그
```

### 4.1 수집 파이프라인 (Ingestion)

1. **커넥터**: 팀 노트, 문서함, 챗, 이메일에서 수집
2. **섹션 분리**: 문서를 의미 단위 섹션으로 분할 (헤딩/문단/화제 전환 기준)
3. **LLM 분류기**: 섹션별로 ① 요약 생성 ② 관리자 등록 키워드 사전 기반 키워드 추출 ③ D등급 제안 + 신뢰도 점수
4. **관리자 검수 큐**: 신뢰도가 임계값 미만이거나 D3 이상 제안된 섹션은 관리자 확인 후 확정. 확정 전까지는 default-deny(제안 등급 중 높은 쪽 적용)
5. **저장**: 벡터 DB에 임베딩 + `{D등급, 키워드, 요약, 마스킹용 엔티티 목록, 출처}` 메타데이터

> A2용 "일반화 요약"과 A1용 "엔티티 목록"을 **수집 시점에 미리 생성**해 둔다. 질의 시점 변환 비용을 없애고, 마스킹 누락 리스크를 줄인다.

### 4.2 질의 파이프라인 (Query) — Phase 2 (추후 구현)

> MVP에서는 이 파이프라인을 구현 범위에서 제외한다. 판정 엔진의 출력(A모드)을 답변 생성이 아니라 **문서 렌더링**에 적용하는 것이 MVP다. 아래는 Phase 2 설계로 보존한다. (참고: 프로토타입 코드 `app/pipeline.py`는 이미 존재하며, 데모에서는 선택적 보너스로만 사용.)

1. **인증 & 컨텍스트 결정**: 사용자 → C등급, 부서, 역할 조회. 채널(내부/외부)과 질의 목적 파악
2. **사전 필터 검색**: 벡터 검색 시 D등급 메타데이터 필터를 함께 적용 — **A4로 판정될 섹션은 아예 검색 결과에 포함하지 않음** (프롬프트에 진입 자체를 차단)
3. **섹션별 모드 적용**: 검색된 각 섹션에 판정 매트릭스 적용
   - A0 → 원문 삽입
   - A1 → "배경 지식 전용, 직접 인용 금지" 태그와 함께 삽입
   - A2 → 미리 생성된 일반화 요약 삽입
   - A3 → 엔티티 마스킹본 삽입
4. **답변 생성**: 변환된 컨텍스트로 LLM 답변 생성
5. **출력 가드**: 생성된 답변을 마스킹된 엔티티 목록·상위 D등급 키워드와 대조 스캔. 유출 감지 시 답변 차단 후 재생성 또는 안내 메시지
6. **감사 로그**: {사용자, 질의, 사용된 섹션과 적용 모드, 답변, 가드 결과} 기록

### 4.3 거버넌스 루프 (지속 고도화)

관리자가 등급 선정을 지속적으로 개선할 수 있는 시스템:

- **감사 로그 대시보드**: 누가 무엇을 물었고 어떤 섹션이 어떤 모드로 쓰였는지 추적
- **재라벨링**: 오분류 발견 시 관리자가 D등급 수정 → 수정 이력이 분류기의 퓨샷 예시로 축적 → 분류 정확도 상승
- **키워드 규칙 관리**: 키워드↔등급 매핑 등록/수정, 신규 키워드 자동 발견 제안
- **정책 시뮬레이션**: 정책 변경 전 "이 변경으로 접근 결과가 바뀌는 섹션/사용자" 미리보기

## 5. 접근 모드별 처리 상세

### A3 정보 마스킹
- 수집 시 추출한 엔티티(고객사명, 금액, 인명 등)를 타입 플레이스홀더로 치환: `[고객사A]`, `[금액]`
- 동일 문서 내 같은 엔티티는 같은 플레이스홀더로 일관 치환 → 답변의 논리적 정합성 유지
- 정규식이 아닌 **수집 시점 LLM 엔티티 추출 결과**를 사용 (변형 표기 누락 방지)

### A2 의미 제한
- 원문이 아니라 수집 시점에 생성한 "일반화 요약"만 컨텍스트에 삽입
- 요약 생성 규칙: 고유명사 제거, 수치는 규모/범위로, 구체적 조건은 카테고리로

### A1 노출 제한 — 가장 주의가 필요한 모드
- 용도: "○○가 가능한가요?" 류의 **판단·집계 질의**에 기밀 데이터를 근거로만 활용
- **MVP에서의 표현**: 뷰어에서 "AI 추론 근거로만 사용 가능" 배지 + 본문 블러 — 판정 결과의 시각화까지만
- Phase 2(실시간 질의응답)에서의 리스크: 원문이 프롬프트에 존재하므로 프롬프트 인젝션으로 유출 가능
- Phase 2 방어 3중화:
  1. 시스템 프롬프트에서 A1 섹션을 명시적으로 격리 태깅
  2. **출력 가드가 최종 방어선** — A1 섹션의 엔티티/키워드가 답변에 등장하면 차단
  3. (강화 옵션) A1 섹션은 별도 추론 패스에서 "예/아니오/개수" 등 구조화된 결론만 뽑아 메인 프롬프트에는 결론만 전달

## 6. 데모 시나리오 — 페르소나별 문서 렌더링 (MVP)

**킬러 장면: 같은 문서를 열어 둔 채 페르소나 드롭다운만 바꾸면, 섹션별 렌더링이 실시간으로 바뀐다.**

### 6.1 뷰어의 섹션 렌더링 규칙 (판정 결과의 시각화)

| 판정 | 렌더링 |
|---|---|
| A0 전체 접근 | 원문 그대로 표시 |
| A1 노출 제한 | 본문 블러/접힘 + "🧠 AI 추론 근거로만 사용 가능 — 직접 열람 불가" 배지 |
| A2 의미 제한 | 원문을 숨기고 **일반화 요약 카드**로 대체 ("제조·금융 등 5개사와 논의 중") |
| A3 정보 마스킹 | 원문 표시하되 엔티티가 `[고객사A]` `[금액A]`로 하이라이트 치환 |
| A4 접근 차단 | 섹션 자체를 잠금 표시(🔒)로 접거나 목록에서 제외 |

각 섹션 옆에 **D등급 배지 + 판정 사유**("gap=-1 → A2", "부서 보정 +1")를 함께 표시해 엔진의 판단 과정을 투명하게 보여준다.

### 6.2 데모 흐름 (문서 하나로 5개 페르소나 순회)

대상 문서: 영업 파이프라인 현황 (D2 고객사 목록 + D3 계약 규모 섹션 혼재), 매출 전망 (D3 + D4 자금 운용)

| 페르소나 | 보이는 것 |
|---|---|
| 외부 고객 C0 | D0 공개 문서만 목록에 존재. 나머지 문서는 전부 잠금 |
| 신입 개발자 C1 | 파이프라인 문서의 D2 섹션은 요약 카드(A2), D3 섹션은 마스킹(A3), D4는 잠금 |
| 영업팀원 C2 | D2 원문(A0), D3는 부서 보정으로 A1 배지, D4 자금 운용은 마스킹(A3) |
| 영업팀장 C3 | D3까지 원문, D4는 A1 노출 제한 |
| CEO C4 | 전 섹션 원문 |

보조 장면: ① 수집 파이프라인 화면 — 원본 문서가 섹션 분리 → 등급·엔티티·요약으로 분류되는 과정, ② 전 페르소나 매트릭스 뷰 — 섹션 × 페르소나 격자에 A0~A4 판정을 한 화면에.

### 6.3 Phase 2 비전: 실시간 질의응답 (슬라이드로만 제시)

발표 슬라이드의 답변 샘플("현재 AI 사업 현황과 향후 전략을 자세하게 알려주세요"에 대한 **C0~C4 전 등급 차등 답변**)이 Phase 2의 목표 UX다. 슬라이드 샘플을 판정 매트릭스로 역산한 전체 표:

| 데이터 | D | C0 | C1 | C2 | C3 | C4 |
|---|---|---|---|---|---|---|
| 공개 사업 방향 | D0 | A0 | A0 | A0 | A0 | A0 |
| 고객사 수·논의 현황 | D2 | A4 (차단) | "10개 이상" (A2) | 18개사·사명 전체 (A0) | A0 | A0 |
| 계약 금액 | D2 | A4 | "수십억원 규모" (A2) | 총 52억·사별 금액 (A0) | A0 | A0 |
| 수익률 | D3 | A4 | "존재하나 제한" (A3) | "30%대" (A2) | "32%" 정확값 (A0) | A0 |
| 가격 전략·경쟁 입찰 | D3 | A4 | (A3) | "경쟁 입찰 진행 중" (A2) | "15% 인하 시 수주 확률 70%" (A0) | A0 |
| M&A 검토 | D4 | A4 | A4 | "[기업명] 인수 검토 중" (A3 마스킹) | **A1: 내용 비공개, 추론에만 반영** — "비공개 최고 전략 정보를 포함하여 분석하면 … 현금흐름 관리가 중요" | SecureAI·120억·9월 이사회 일정 전체 (A0) |

C3 행의 M&A 칸이 이 솔루션의 백미다: **AI가 기밀을 발설하지 않으면서도 기밀을 반영한 더 나은 조언을 한다** (A1 노출 제한). C4 답변은 전 등급 정보를 종합한 전략 제언까지 포함한다.

Phase 2에는 **단계적 투명성(graduated transparency)** 답변 표출 규칙도 포함한다: 접근이 제한된 정보의 "존재"를 등급에 맞게 고지 — gap −1~−2 구간은 "정보가 존재하지만 제한됨"을 알리고(C3 샘플의 *"비공개 최고 전략 정보를 포함하여 분석하면"*이 그 예), gap −3 이하는 존재 자체를 은닉한다.

발표 구성의 **"접근 권한 분석"** 슬라이드는 데모 UI의 판정 매트릭스 뷰·섹션별 판정 사유 표시가 대응한다 — 어떤 데이터가 어떤 규칙으로 어떤 모드가 되었는지의 투명한 분석.

## 7. MVP 범위 (하루짜리 해커톤 기준 — 확정)

> 목표: **입력 데이터를 정해진 보안 등급으로 분류하고, 페르소나에 따라 접근이 제어되는 것을 시각적으로 증명한다.** 실시간 질의응답은 Phase 2다.
> 부수 이점: LLM은 수집(분류) 단계에만 쓰이므로 **데모 자체는 API 호출 없이 완전히 결정론적으로 동작**한다 — 라이브 데모 리스크 제거.

### ✅ 반드시 구현 (P0)
1. **시드 데이터**: 가상 회사 문서 12개 (영업 파이프라인, 계약, 매출 전망, 인사/M&A, 공개 제품 문서 — D0~D4 혼재)
2. **수집 파이프라인 (1회 실행)**: 섹션 분리 + D등급 분류 + 엔티티 추출 + A2용 요약 → `sections.json` 고정·커밋 (데모 중 분류 변수 제거)
3. **판정 엔진**: gap 매트릭스 + 컨텍스트 보정, 순수 파이썬 + YAML 정책
4. **문서 뷰어 시각화 UI**: 페르소나 드롭다운 + 6.1절 렌더링 규칙(원문/블러+배지/요약 카드/마스킹 하이라이트/잠금) + 섹션별 D등급 배지와 판정 사유 표시
5. **전 페르소나 매트릭스 뷰**: 섹션 × 페르소나 격자에 A0~A4 판정 히트맵

### ⚠️ 시간 남으면 (데모 임팩트 순)
6. 수집 과정 시각화 — 원본 문서가 섹션·등급·엔티티로 분해되는 화면
7. 감사 로그 테이블 (누가 어떤 문서를 어떤 모드로 열람했는지)
8. (보너스) 실시간 질의응답 데모 — 이미 구현된 `app/pipeline.py` 활용, API 키 있을 때만

### ❌ 하루에는 하지 않음 (슬라이드로만)
- **실시간 질의응답 파이프라인 (Phase 2)** — 모드별 변환 프롬프트 삽입, 출력 가드, A1 답변 동작, 단계적 투명성
- 벡터 DB / RAG
- 관리자 콘솔(검수 큐, 키워드 규칙 UI, 재라벨링) — "거버넌스 루프" 슬라이드 1장
- 실서비스 커넥터(Slack/Notion/메일), SSO/실조직도 연동 — 하드코딩된 페르소나로 대체
- 이메일/챗 전송 시점 DLP (사람↔사람 접근 제어) — 아키텍처만 문서화

### 데모 리허설 체크리스트
- 대표 문서 2개 × 페르소나 5개 = 10개 화면 전부 사전 확인, 판정이 어색한 섹션은 라벨 조정
- 마지막 1시간은 리허설 전용

## 8. 기술 스택 제안

| 레이어 | 선택 | 이유 |
|---|---|---|
| LLM (수집 단계만) | Claude API — 분류·요약·엔티티 추출 | MVP에서 LLM은 수집 시 1회만 사용, 데모는 API 없이 동작 |
| 판정·정책 | YAML 정책 파일 + 순수 파이썬 판정 함수 | 판정은 반드시 결정론적·감사 가능해야 함 |
| 프론트 | Streamlit (문서 뷰어 + 매트릭스 뷰) | 해커톤 속도 우선 |
| 데이터 | JSON (`sections.json`) | 충분 |
| (Phase 2) 벡터 저장소 | ChromaDB (로컬) | 메타데이터 필터 지원 + 설치 부담 없음 |
| (Phase 2) 생성 LLM | Claude API | 질의응답 답변 생성 |

**설계 원칙: 판정(Engine)은 결정론적 코드, 이해(분류·요약·추출)만 LLM.** 접근 제어 판단 자체를 LLM에 맡기면 감사 불가능하고 인젝션에 취약해진다.

## 9. 핵심 리스크와 설계 결정

| 리스크 | 대응 |
|---|---|
| LLM 분류 오류 (D3을 D1로) | 신뢰도 임계값 + default-deny + 관리자 검수 큐 + 재라벨링 루프 |
| A1 프롬프트 인젝션 유출 | 출력 가드(엔티티 대조 스캔)를 최종 방어선으로. 판정 로직에는 LLM 미사용 |
| 마스킹 누락 (변형 표기) | 정규식이 아닌 수집 시점 LLM 엔티티 추출 + 출력 가드 이중화 |
| 추론 기반 재구성 공격 (여러 A2 답변 조합으로 원본 추정) | 감사 로그 기반 반복 질의 패턴 감지 — 로드맵 명시 |
| 문서 수정 시 등급 불일치 | 재수집 시 섹션 해시 비교로 변경 섹션만 재분류 |

## 10. 확장 로드맵

### Phase 1 — 분류 + 판정 + 시각화 (해커톤 MVP, 현재)
입력 데이터를 보안 등급으로 분류하고, 페르소나별 접근 제어를 문서 뷰어로 시각적으로 증명.

### Phase 2 — 실시간 AI 질의응답
판정 엔진의 출력을 문서 렌더링이 아니라 **LLM 컨텍스트 조립**에 적용 (4.2절 설계):
- 모드별 변환 삽입(A0 원문 / A1 배경 전용 태그 / A2 요약 / A3 마스킹본) → 답변 생성 → 출력 가드(엔티티 대조 스캔)
- **단계적 투명성** 답변 표출 규칙: 제한된 정보의 존재를 등급에 맞게 고지 (gap −1~−2: "존재하나 제한됨" 고지, gap ≤−3: 존재 은닉) — 발표 슬라이드의 C0/C1/C2 답변 샘플이 목표 UX
- 실데이터 규모 확장 시 D등급 메타데이터 사전 필터가 붙은 벡터 검색(RAG) 도입
- 거버넌스 루프(검수 큐, 재라벨링, 키워드 규칙, 정책 시뮬레이션) 정식화

### Phase 3 — "사람↔사람" 접근 제어 (DLP 확장)
같은 엔진을 AI 질의 외의 데이터 이동 경로에 적용:
- **이메일/챗 전송 시**: 발신 내용의 섹션을 실시간 분류 → 수신자 C등급 기준 판정 → 전송 차단이 아니라 **"수신자 등급에 맞게 마스킹/요약해서 보내기" 제안** (기존 DLP와의 차별점: 차단이 아닌 변환)
- **문서 공유 시**: 공유 대상별로 같은 문서의 다른 뷰(마스킹본/요약본) 자동 생성
- **외부 공유 링크**: C0 기준 변환본만 노출

Phase 3이 "모든 데이터를 사람과 AI가 최대한 활용"이라는 비전의 완성형이며, 해커톤에서는 비전 슬라이드로만 제시한다.
